## 3. 开机启动流程

### 3.1 Systemd 服务：weread-selenium.service

```ini
[Unit]
Description=WeRead Selenium Container
After=network-online.target docker.service
Requires=docker.service
Wants=network-online.target

[Service]
Type=oneshot
RemainAfterExit=yes
ExecStartPre=/bin/sleep 180                          # 等待 3 分钟让网络就绪
ExecStartPre=/bin/bash -c "while ! docker ps ...; do sleep 2; done"  # 等待 Docker 可用
ExecStartPre=/bin/rm -f /tmp/.X*-lock /tmp/.X11-unix/X* 2>/dev/null || true  # 清理残留锁
ExecStart=/usr/bin/docker compose -f .../docker-compose.yml up -d selenium
ExecStop=/usr/bin/docker compose -f .../docker-compose.yml down

[Install]
WantedBy=multi-user.target
```

- **本次启动时间线**：

## 7. 问题与建议

### 问题

1. **jpx155 / jpx181 缺少 cookies.json** — 每次运行都需要扫码，无法自动化
2. **jpx155 Chrome renderer timeout** — Selenium 在高负载下可能出现浏览器超时
3. **Selenium CPU 占用 83%** — 在 ARM (RK3566) 上 Chromium 本身消耗较大
4. **旧镜像未清理** — selenium:144.0 占用 2.16 GB

### 建议

1. 为 jpx155、jpx181 手动扫码登录一次以生成 cookies.json，后续可自动复用
2. 考虑在 Selenium 容器中降低 Chromium 的并发会话数，或在 app 脚本中增加重试逻辑
3. 执行 `docker image prune` 或 `docker rmi selenium/standalone-chromium:144.0` 释放磁盘空间
4. 监控 Bark 推送配置 — 当前所有用户均未配置 Bark 密钥，异常时无法远程通知
